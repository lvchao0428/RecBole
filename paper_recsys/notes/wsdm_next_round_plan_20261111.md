## B. 老师判断里已经锁定的结论

这些是老师已经下的判断，不是待跑出来的新结果。

问题有价值，实验认真，可复现性不错。现有证据撑不住比较广的 claim。「观察到了什么」写得比「为什么发生、别人应该怎么办」更充分。

审稿人不是只想看 SOTA，也不是没看懂这是实证研究。缺口是：发现还绑在一套具体 config 上，也就是自己的四个 prompt、一个 encoder、一种融合。要变成别人可以复用的知识，才算补上这一层。

方向和现有资产继续用：数据处理、time-split protocol、文本特征、复现框架、实验记录。不另起一个完全不同的大模型课题。也不把现稿做一次小修就算下一轮。1104 写这句的时候，针对的是冲 WSDM 这一档；1105 说即使转 C 类，贡献边界、范围和解释深度仍然要解决。所以「现稿直接再投」只对应他所说的那种 C 类水会，不是本计划要交的那一篇。

下一轮主问题用他的这句：

> 在时间一致的推荐 evaluation 下，什么样的文本视角真正带来了额外的任务信息，什么样的只是增加了表示差异和计算成本。

1105 把同一件事收成：先查清不同视角到底有没有带来新的任务信息。

路线先走机制型的受控研究：把视角怎么构造、怎么编码、时间评测各自的作用分开，并写出适用边界。轻量的视角选择或使用规则，只有机制结果支持时才开。它不必是复杂网络，也不能只是把一个已有 gate 换名。不要为了「有新方法」把 SE、Cross、boost 加回来。负结果不会自动够投稿。

指导方式也改了：先设证据门槛，再定投稿位置。Findings 或某个等级的刊会不再当保底。Stop 条件是他带 13、14 期时开始用的做法，用来避免在一个 idea 上耗太久。

## C. 四位 reviewer：只映射到最小实验

不按 `wsdm2027_1079_reviews.md` 把每条意见补一遍。下面只保留老师指定的那一层。

**R1。** 要的是解释和可操作性，不是更复杂的模型。两件要分开的事：

- Last 和 Random 为什么会改变方法排序。放到阶段 3 的锚点：固定 checkpoint、同一批事件、Successive，再按事件位置、距 cutoff 的时间、历史长度、目标 item 频次看相对 TF-IDF 的增益。
- 多视角效果不好，是 prompt、encoder、pooling，还是输入本来就没有新信息。放到阶段 2，一次只动一个因素。

R1 举例的 weighted fusion、contrastive、gating 不在这个映射里。见上面的冲突 5。

**R2。** 数值接近时，均值排序不是稳健性。要交代差异的不确定性、适用范围和实际价值。阶段 3 的正式结果报配对差异和置信区间，并保留逐用户或逐事件输出。一个 std 不是等价。很小的 p 值不是实际收益已经够大。适用范围沿用 warm-only，除非分层结果自己把边界说清。

**R3。** 老师认为他已经比较准确地理解并认可了论文定位。他的建议直接变成实验，而不是再写一段定位：

- 另一个 encoder、不同的 prompt / view 家族：阶段 2。
- Successive、warm-target 边界：阶段 3 的锚点。warm-only 继续写明。不为这一点单做一套零交互、冷启动推荐系统。
- 非 Amazon：阶段 3 的一个场景，用来回答跨场景，不用来代替机制实验。

**R4。** 不能从「自己的四个 prompt + 一个 encoder + 一种融合」推广成多视角推荐普遍冗余。要有一个外部多 prompt 方法进入比较。老师点名从 LLM-Rec、SC-Rec 里按输入、输出和训练设定选最相关的一个；没有更贴的就选最贴的那一个。先读原文。改了主要输入或训练流程，就标注改编，不写成完整复现。内部几行模型互相比，回答不了 R4。

三个外推问题不要并成一张大表：第二个 encoder 回答是否依赖 Qwen；外部方法回答是不是只是自己这四个 prompt 的构造；非 Amazon 回答能否跨场景。第二个 encoder 放在阶段 2 做。阶段 3 不再把 encoder 和其他两个因素做全交叉。

## D. 明确不要做的事

当作操作清单。和阶段产出冲突时，以这张清单为准。

**范围和投稿**

- 不把四位审稿人的每条意见都补一遍。
- 不换标题，不靠加一个数据集或一个模型再润色，把现稿重投。
- 不把现稿小修当成下一轮。
- 不另起一个完全不同的大模型课题。
- 不为了让 multi-view 超过所有 baseline 去堆新模块。
- 不为了「有新方法」把 SE、Cross、boost 加回来。
- 不把已有 gate 换个名字，称为视角选择方法。
- 不把负结果预先当成已经够投稿。负结果要能排除其他解释，并且后面的工作用得上。
- 不把 Findings 或某个等级的会当成保底。
- 不赶 2026-11-20 的 PAKDD。也不按「哪个截稿最近」选会。
- 一篇实质相同的文章，不同时处于两个正式出版会议的审稿中。审稿期间可以继续做研究。另一篇准备好了，也不能直接并行再投。转投要先按原会议规则撤稿，并确认撤稿已经生效。录用之后，撤稿不是换会的办法。
- 「相比上一版排除了什么解释、新增了什么可迁移的认识」写不出来时，不靠改写准备投稿。

**实验**

- 不做所有模型 × 所有数据集 × 所有视角的全网格。
- 不把实体 coverage 优化到 90%，也不把 coverage 高当成阶段 1 的通过标准。
- 不用大模型编造原文没有的属性或实体来填满 view。缺失保持缺失，后面用 mask 或 gate 处理。
- 不用带 global temporal overlap 的旧 LOO 选择新路线或新模型。旧 LOO 只可以留作协议对照。主实验是 leakage-free 的 GTS。
- 不因为旧 LOO 更容易排出好看的模型层级，就用它指导选择。
- 阶段 2 一开始不把全部组合跑满多种子。
- 查 pooling 时，只改 pooling。不同时换 encoder、输入和融合结构。
- 不优先 DeepSeek-R1-Distill。这不是一篇 scaling law。
- 不把第四个 Amazon category 当成非 Amazon 场景。
- 不维护原来的方法层级。阶段 2 的 stop 不是「multi-view 终于赢了」。
- 不从 score entropy 或集中度图倒推 Last / Random 的故事。
- 不为了 warm-only 临时加一套零交互推荐系统。
- 外部方法改过主要输入或训练流程时，不写成原论文的完整复现。
- 表示空间变了、推荐效果没有变时，不把这条结论删掉。

**数据和 agent**

- 实验 agent 不改原始数据、split manifest、正式 evaluation 脚本。这三类改动单独审查。
- 探索阶段不让 agent 自由查看已经锁定的确认用 test。已经反复看过的旧 test 可以用于探索和复盘；关键 claim 的确认要放在新的时间窗口或外部数据上。
- 不因为某个 seed 结果不理想或方差大就删掉它。只有事先约定的程序故障可以排除，并且留下 log。
- 失败、下降、无增益的 run 都保存。不只留成功的。
- 每个实验用独立分支或工作目录。多个 agent 不同时改同一套代码。
- 这些约束要落在文件权限、hooks 和分支上。不靠在 prompt 里写一句「请遵守」。老师这句原文到逗号为止，后半句没有写完；执行时按他同一段里的权限和分支要求做，不补一句新的提示词就算完成。
- 不给 agent「把论文改得更强」或「把模型改到期待的排序」。

**写作**

- AI 不改已经锁定的数字、protocol、citation、模型版本和贡献范围。已知的事实错误不再犯：valid 写成 test，GTS-All 混进 Last，改 seed，引用放错位置。
- 不为了段落顺滑自动补一个解释。没有来源的判断标成「待核查」。
- 不把已有证据的贡献写弱，并在摘要和引言里叠「我们没有提出新模型」「我们只是观察到」「虽然范围有限」「不能说明什么」。
- 尚未验证的机制不写成事实。
- 真正改变结论的局限写在对应结果旁边，不全部留到文末的 limitations。
- 不让模型只从「否定作者」的方向改稿。事实审计和贡献是否被写丢，分成两轮。

## E. 合并后的行动步骤（从 2026-11-11 起）

1104 的 (1)(2)(3)(4) 和 1105 的 (1)(2)(3) 合成下面三阶段。前一阶段的产出冻结之后，才开始下一阶段的正式运行。写作里的问题、实验设计和相关工作可以并行；摘要和贡献点等证据稳定后再锁。

### 阶段 1 — 大约 1 周（冻结、审计、小样本抽取）

大约到 2026-11-18。这一周不投稿。2026-11-20 的 PAKDD 不提交。

这一阶段不重跑全部实验。目的是让后面的比较站在同一套实现上，并决定哪些抽取出的 view 值得训练。

**产出**

1. **冻结对照表。** 当前论文版本、代码 commit、数据划分、特征文件、主表结果，五者对齐。投稿用的是哪一版 tex，在表上写明。skill 把 `main_wsdm2027_v3_0822.tex` 标成 stable mainline，把 `main_wsdm2027_v3_0823.tex` 标成后来的 de-AI 工作稿。本计划不把其中某一个当成投稿版。
2. **一页 experiment protocol。** 主评测写明是 leakage-free GTS。旧的、带全局时间重叠的 LOO 只作协议对照，不参与选型。写明探索可以用已经看过的 test，关键 claim 的确认集是「没有用来反复调参的时间窗口或外部数据」。确认集在探索时不打开。
3. **能自动跑的检查。** 通过后冻结，不因为某一组指标不好看就改。
   - Early 的特征统计只在 Early cutoff 之前拟合。
   - Last、Random、Successive 使用同一套历史构造和候选规则。
   - 各模型的 alignment、融合容量、训练开关一致。
   - 特征文件 hash。
   - config diff、数据的时间边界。
4. **Seed 列表事先固定。** 从主表已经使用的记录原样抄出。本计划不新指定 seed。排除规则只保留事先写明的程序故障，log 保留。
5. **少量 item 上的抽取试做。** 从原始文本抽取有依据的属性或实体，例如属性、功能、适用对象。每条能指回原文；原文没有的信息允许为空。人工抽查：原文归因、coverage、正确率、幻觉比例、不同 item 频次下的缺失。缺失保持缺失。

**Stop。** 协议和检查已经冻结，并且能够说出哪些抽取出的 view 值得进入训练。

停的标准不是 coverage 高，也不是某个模型排序好看。coverage 高不代表信息有用，也不代表下游更稳。有的 item 本来就没有明确的适用对象或功能属性。

**这一阶段打开的决定。** 阶段 2 训练哪些 view。不打开投稿会，也不打开「多视角是否有效」的结论。

### 阶段 2 — 2–3 周（小的受控实验）

阶段 1 冻结之后再开始。大约两到三周。这是小型受控实验，不是更大的模型。

**先固定、再比较**

- 固定下游 backbone、总维度、调参预算。三者在这阶段的正式比较里不变。
- 先做 Beauty。
- 比较四臂：
  1. 当前问法式 multi-view：不同问法与同一份商品文本拼接，读 hidden states 再 pooling。不是四份内容不同的生成回答。
  2. 实体 / 属性式 multi-view：内容组织相对原文有变化，而且能追溯到原文。
  3. single-view。
  4. 便宜对照：把同一份 single-view 特征重复成相同数量的分支、相近容量。

**开跑之前写明两种结果分别意味着什么。** 老师没有代写这两句。实验卡片里要有人写、有人批准。下面只是和 stop 条件对齐的对照，批准时可以改措辞，不能改成「多视角赢了才算这一阶段成功」：

- 内容有变化的多视角不优于重复视角：分支数和容量对齐之后，优势没有超出「同一份特征复制多份」。这一支更靠近输入视角重复，或没有稳定的额外任务信息。它单独证明不了 encoder 不合适。
- 内容有变化的多视角优于重复视角：超出容量对照的那一部分来自视角内容不同。这只是额外差异。是不是任务信息，看下游，不单看 CKA 或 effective rank。
- 问法式和实体式分开读。问法式仍然是同一份文本换问法。两者都高相似，更靠近「encoder 把不同信息编得很像」，或抽出来的内容仍然没有额外任务信息。问法式高相似而实体式分开，更靠近「原先的高相似度来自输入重复」。

**Encoder。** 保留 Qwen2.5-7B-Instruct 作为原始对照（现稿 checkpoint；老师简称 Qwen2.5-7B）。再加一个，优先 Qwen3-Embedding-8B，因为老师说它是面向文本表征训练的。只有问题是模型家族差异时，才用 Llama3.1-8B 或其他合适 encoder。不优先 DeepSeek-R1-Distill。选 1–2 个 encoder，不做 scaling。

**一次只动一个因素。** 若查 pooling，同一个 encoder、同一份输入，只改 pooling。

**运行顺序。** 不先把每个组合跑满多种子。先检查编码是否符合该模型的用法，以及表示分析是否可信。再把最能区分假设的 config 送进推荐训练。指标顺序：CKA、effective rank、view ablation，然后下游评测。表示变了、推荐没有稳定变化，就保留这个结论。

**Stop。** 能够回答：当前问题更接近输入视角重复、编码方式不合适，还是确实没有稳定的额外任务信息。三种答案对应三种论文结论。不需要保住原来的层级。

停的标准不是 multi-view 终于赢了。

**这一阶段打开的决定。** 阶段 3 是做「确认一个已经分开的现象」，还是转入「收窄 claim、停止加实验」。打不开「已经可以投稿」。

### 阶段 3 — 1–2 周（锚点、有限外推、然后定会和定 claim）

只有阶段 2 给出了稳定现象，评测锚点和外推才做。若阶段 2 的结果只是「这四个 Qwen 问法又一次不如 TF-IDF」，而且其他解释还没有被排除，就不要把阶段 3 做成新的大实验。控制算力和时间，收窄论文和会。确认实验缩成：在一个没有反复调参的窗口上，用固定 config 看这个负结果是否还在。

阶段 3 的时间盒是 1–2 周。1104 的锚点和外推都还在范围内，但必须放进这个盒子。放不下时按下面的顺序砍，不追加第四个阶段：

1. 确认实验一定做。这是 1105 阶段 3 的核心，也是任何准备写进论文的 claim 的门槛。
2. 现象已经稳定时，做 Successive 锚点和四项分层。权重要冻结，这一项相对便宜，用来回答 R1 的 Last / Random。
3. 阶段 2 还没回答的那一个外推问题再做一件：非 Amazon，或一个外部方法。阶段 2 已经做了第二个 encoder 的，不再为了「Qwen 依赖性」重开一轮 encoder 网格。
4. 不做模型 × 数据集 × 视角的全交叉。

**评测锚点（1104 的第 3 阶段，现象稳定才做）**

- 固定 checkpoint，固定用户样本，补 Successive。权重不更新。
- 每个事件只用当时已经发生的历史。
- 从同一批事件计算 Last、Random 和逐事件指标。
- 同一事件集合、同一过滤、同一用户权重下：Random 是用户内平均事件表现的一种抽样估计；Last 是窗口里的最后一个事件。排序不同，不自动说明其中一个错了。先写明部署时要预测的是什么。老师指出，《Time to Split》把 Last、Random、Successive 看成不同但有联系的评测选择（原文拼写是 evaluaiton），不是要求所有场景只有一种正确答案。
- 比较文本方案相对 TF-IDF 的增益是否随事件位置、距 cutoff 的时间、用户历史长度、目标 item 频次变化。
- 差异主要由目标构成解释，就把构成效应写清。分层之后仍在，就写还有未解释的部分。warm-only 继续写明。

**有限外推（1104 的第 4 阶段，缩进 1–2 周）**

- 一个带可靠时间戳和文本的非 Amazon 数据集。不是第四个 Amazon category。
- 方法行保留 ID-only、TF-IDF、single-view、multi-view。
- 读完 LLM-Rec 和 SC-Rec（或最接近的那一篇）之后，选一个外部 baseline。改编处标注。相关工作的阅读可以在阶段 2 并行，正式运行放在阶段 3，并且只在阶段 2 的现象值得外推时运行。
- 三个问题保持分开：encoder 是否依赖 Qwen（阶段 2 已做则这里不重做）；外部方法是否说明问题只出在自己的四个 prompt；非 Amazon 是否跨场景。

**确认**

- 使用一个没有用来反复调参的数据集或时间窗口。Beauty 是阶段 2 的探索集，不能再把 Beauty 上反复看过的 test 当成这次锁定确认。
- 固定 config，多种子，事先固定的 seed，相同调参预算。
- 保留逐用户或逐事件输出。报告配对差异和置信区间。
- 不同 encoder、不同 view 构造若出现一致现象，可以考虑较高水平的实证论文。效果若只限于特定 prompt 或某个数据集，收窄 claim，选匹配的 C 类，停止加实验。

**写作。** 问题、实验设计、相关工作可以与实验并行。摘要和贡献点保持未锁，直到上面的确认结果稳定。定稿前要能写出：相比上一版，排除了哪些解释，新增了什么可迁移的认识。写不出这句，就不进入投稿文本。

**阶段 3 之后的决定（三选一，不并行铺开）**

- 若单看 CKA 或 effective rank 预测不了某个 view 有没有下游收益，但验证集上的边际收益或稳定性可以判断：可以研究一个低成本视角选择规则。这仍是待验证的想法。先查相关工作，再和随机选 view、按几何多样性选 view、固定 single-view、使用全部 view 比较。在此之前不称为新方法。它不能是改名后的已有 gate。
- 若没有有用的选择规则，但干预已经说明多视角在什么条件下有用、什么条件下无用：写机制型实证论文。较好的会仍然可以考虑。
- 若结果只是又一次「这四个 Qwen prompt 不如 TF-IDF」：封顶算力和时间，收窄论文和会。不强制再投同一等级。

论文不会因为措辞改好了就可以投。可以投稿的条件是上一句「排除了什么、新增了什么可迁移认识」写得出来，而且对应的是冻结协议下的确认结果。

## G. AI 工作流（实验和写作分开）

老师建议把 Codex 和 Claude Code 放进受控流程。同学是第九期；他说明当时课上没有着重讲 Agentic AI。仓库里已有实验日报和一些 skill，可以继续用。本计划不新建 `AGENTS.md` / `CLAUDE.md`。等阶段 1 的协议冻结后，再把数据 protocol、baseline、搜索空间和禁止修改的文件写进这些文件。约束用文件、权限和 hooks 执行。

实验循环固定为：

> 假设 → 人工批准实验卡片 → AI 实现 → 自动检查 → 小样本试跑 → 批准正式运行 → 保存全部结果 → 独立审计 → 人工定结论

老师原文的箭头是 `假设->人工批准实验卡片-》AI实现-》...`，支持或反对假设写成了「反驶」。卡片上的字段用「支持或反驳」。

每张卡片只写：要回答的问题、唯一主要改动、哪些文件不能动、比较对象、预算、验证指标、什么结果支持假设、什么结果反驳假设。完成与否要能检查。

可以借鉴 autoresearch 的循环：固定评测边界，限定修改范围，运行，记录，保留或回退。不借鉴它的目标。原项目是在固定预算下把验证指标往上优化；这里不能跑到出现期待的模型层级为止。

登记表字段：commit、config、seed、cutoff、特征文件 hash、checkpoint、结果路径。论文里的每一张表都要能从这些记录重新生成。每次新实验从固定 commit 拉分支，只改指定模块，并自动比较 config、跑测试、记下指标和代码版本。AI 可以减少重复劳动。它不能同时自由修改模型、评测方式、实验结果和论文结论。

写作分开做：

- 先锁定数字、protocol、citation、模型版本、贡献范围。AI 只改句子。
- 每次一个章节。输出原句、改句、修改理由、对应证据。人看 diff。
- 没有来源的判断标「待核查」。
- 两轮：第一轮只做事实和逻辑审计；第二轮检查有证据的贡献有没有被写丢。有证据的结论写清楚；没有实验支撑的机制保留不确定性。
- 让 AI 改之前，先有一份贡献–证据–边界表。

老师举的句式，下一版用来开头，而不是用来加承诺。他对比的是：不要写「我们没有提出新的架构，只进行了一项范围有限的实证研究」；要写实际做过的比较——在共享推荐 backbone 下控制文本输入和评测目标，量化它们对方法比较的影响——然后说明测试了哪些数据、encoder 和场景。

可选工具，现在不克隆、不运行：[game-the-llm-reviewer](https://github.com/Michael-Jiahao-Zhang/game-the-llm-reviewer)。老师说第六期有同学用过，那篇后来被 KDD 录用。等证据稳定之后可以试。它不代替事实锁定和两轮检查。
