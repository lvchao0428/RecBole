--------------- 审稿意见 1 (R1) ---------------

投稿编号: 196
标题: MV-Align: Multi-View Text Alignment
with Explicit Feature Crossing
for Sequential Recommendation

----------- 优点 -----------
- 方法描述足够详细，支持可复现性，且代码已公开。
- 模型明确针对冷启动场景进行设计。
- 实验结果讨论清晰，为从业者提供了实践指导。
  论文包含了模型复杂度分析。

----------- 缺点 -----------

引言部分需要改进
- 摘要中呈现的研究问题和目标与引言中提出的存在
  显著不一致。因此，研究问题和贡献都不够清晰，
  也未能充分置于该主题现有研究体系中。
- 研究问题（RQ）相当简单，大多只涉及设计决策
  对评估结果的影响。一般来说，研究问题应该足够
  复杂，需要批判性分析而非简单的是/否回答。
  此外，研究问题应在提出研究问题之后、介绍贡献
  之前呈现。

设计选择缺乏充分的动机阐述
- 为什么选择SASRec而不是其他序列推荐模型？
- 提到了几种失败模式（failure modes），但这些
  既没有先前文献支持，也没有专门的实验验证。
- 为什么建模ID embedding和text embedding之间
  的特征级交互（feature-level interactions）
  很重要？
- 为什么选择了这些特定的多视角表示？

相关工作
- 相关工作部分相当肤浅。
- 此外，先前工作与所提方法之间的比较没有清晰
  阐述，难以评估论文的原创性和实际贡献。

基线方法
- 基线方法实际上是所提模型的消融实验，而非来自
  相关工作的强独立基线。

----------- 评分 -----------
与会议主题的相关性:  5（强相关）
原创性:              3（中等）
相关文献覆盖:        2（薄弱）
技术严谨性:          3（基本合格）
整体表述:            3（基本合格）
影响力:              3（中等）
方法可复现性:        4（高度可复现）

----------- 补充评论 -----------
- LLMs、CTR、HR、DCN等缩写在首次使用时未定义。

引言部分
- 第一段缺少支持其论述的参考文献。
- 引言中"Prepare"步骤讨论的失败模式
  （failure modes）不够清晰。描述应改进并配以
  示例。它们的含义要到后面方法部分才能勉强理解。

局限性与未来工作
- 论文没有讨论局限性。
- 也缺少未来工作部分，尽管页面限制似乎并未被
  完全利用。


--------------- 审稿意见 2 (R2) ---------------

投稿编号: 196
标题: MV-Align: Multi-View Text Alignment
with Explicit Feature Crossing
for Sequential Recommendation

----------- 优点 -----------
- S1: 论文提出了一个有趣的想法，用多视角表示
  物品文本并显式建模特征交叉。
- S2: 代码已公开。
- S3: 论文在严格的实验设置下进行了实验（采用
  全排序设置而非广受诟病的采样设置；基于四次
  不同随机种子的独立运行报告均值和标准差）。

----------- 缺点 -----------
- W1: 论文缺少使用文本特征的基线方法。
- W2: 实验中只使用了一种骨干模型。
- W3: 实验中只考虑了一个领域。
  [译注: 这是事实性错误，论文实际在Beauty和
  Toys&Games两个数据集上做了实验]
- W4: 所提方法似乎无法处理新物品。
- W5: 每个视角的细节和有效性不够清晰。
- W6: Cross network组件倾向于使HR指标恶化。

----------- 评分 -----------
与会议主题的相关性:  5（强相关）
原创性:              3（中等）
相关文献覆盖:        2（薄弱）
技术严谨性:          2（技术严谨性不足）
整体表述:            3（基本合格）
影响力:              2（有限）
方法可复现性:        4（高度可复现）

----------- 详细审稿意见 -----------
本文提出了MV-Align，一个配备多视角文本对齐和
显式特征交叉的序列推荐框架。论文在想法、可复现性
和严谨性方面有若干优点。但在发表之前有许多问题
可能需要解决。

问题详情如下。

W1: 论文缺少使用文本特征的基线方法。
- 现有研究包括FDSA、S3-Rec和UniSRec。论文应将
  所提方法与这些研究（或更新的研究）进行比较。

W2: 实验中只使用了一种骨干模型。
- 虽然本文提出了一个序列推荐框架，但实验中只使用
  了SASRec作为骨干模型。所提方法对其他序列推荐
  模型的泛化能力仍不清楚。

W3: 实验中只考虑了一个领域。
- 实验中只使用了Amazon数据集。需要更多数据集
  （如MovieLens）来证明所提方法在其他领域和平台
  上的有效性。

W4: 所提方法似乎无法处理新物品。
- 尽管论文关注冷启动场景，但不清楚如何为训练数据
  中未出现的新物品准备ID embedding。
- 在实验中，目标物品按流行度分组，最低阈值为1次
  交互。这意味着没有使用真正的新物品来考察所提
  方法在冷启动场景中的性能。

W5: 每个视角的细节和有效性不够清晰。
- 每个视角使用了什么提示词（prompt）？
- 虽然消融研究比较了多视角和单视角设置，但各个
  视角单独的有效性仍不清楚。

W6: Cross network组件倾向于使HR指标恶化。
- 鉴于实验结果，论文建议在候选召回时禁用（或在
  最终排序时启用）cross network组件。但在前一种
  情况下，更轻量、更快速的模型会更可取。
- 不清楚这是所提方法特有的问题，还是使用类似组件
  的方法的共性问题。

其他评论：
- 第3.2节：$\theta_v$是什么？它是否与公式6的
  输出相同（尽管变量名不同）？
- 第3.3节：虽然$\alpha_i$被简要解释了，但其
  数学定义不够清晰。
- 表3：所提方法在new层的HR@10分数被加粗高亮，
  但在该条件下所提方法并非表现最好的。
  [译注: 这是一个有效的批评，Beauty数据集上
  new层的HR@10确实是ID-only更高(1.88 vs 1.76)]


--------------- 审稿意见 3 (R3) ---------------

投稿编号: 196
标题: MV-Align: Multi-View Text Alignment
with Explicit Feature Crossing
for Sequential Recommendation

----------- 优点 -----------
1. 严谨、透明、详尽的实验
2. 论文贡献了一些有趣且有用的实证发现，即TF-IDF
   是一个出乎意料的强基线，以及cross network
   决定的HR-ranking trade-off影响部署选择
3. 代码、配置文件和运行脚本在基于RecBole的匿名
   仓库中发布，使用公开数据集，确保了强可复现性

----------- 缺点 -----------
1. 框架的复杂度可能不能被其边际收益所证明，且
   作者自己的消融实验暗示存在近乎冗余的组件。
   MV-Align在SASRec之上堆叠了许多部件（即：
   四个LLM提示视角、逐视角SVD、ZCA白化、SE风格
   门控、ℓ2归一化、可学习视角门控、DCN-V2
   cross network、多视角InfoNCE对齐、分别的
   训练时和推理时冷启动重加权，以及两阶段训练
   方案），每个都有自己的超参数。然而，完整流水线
   仅比最佳文本基线（TF-IDF+单视角LLM）提高约
   3% HR@10（Beauty 5.62→5.79；Toys 6.39→
   6.61），而大部分文本收益已经来自廉价的TF-IDF。
   此外，论文自己的消融实验报告移除SE门控仅造成
   "边际变化"，白化仅对所选择的多视角设计有效。
   增益虽然统计显著（经过良好测试），但设计复杂度
   和调参空间并未被边际收益清晰证明。

2. 范围狭窄且未评估外部基线。评估覆盖两个相似的、
   非常稀疏的Amazon领域，一个骨干（SASRec），
   一个LLM（Qwen2.5-7B）。刻意的分层基线设计
   意味着没有与现有文本增强序列推荐模型比较，因此
   MV-Align与其他方法的竞争力，以及发现在不同
   领域/骨干/LLM上的泛化性，都未被建立。

3. MV-Align将已有组件（如SASRec、DCN-V2 cross
   network、SENet风格门控、ZCA白化、InfoNCE
   对齐、多提示LLM视角）组装成一个新方案。这种
   组合以及DCN-V2在序列推荐中ID×Text融合的应用
   是合理的，但没有单个元素是新颖的。

----------- 评分 -----------
与会议主题的相关性:  5（强相关）
原创性:              2（有限）
相关文献覆盖:        4（较强）
技术严谨性:          4（技术严谨性强）
整体表述:            4（表述良好）
影响力:              2（有限）
方法可复现性:        4（高度可复现）

----------- 详细审稿意见 -----------
这是一项详尽的实证研究。评估协议是一个明显的优势：
全排序指标（而非采样）、四个随机种子并报告方差、
在大规模测试集上对最强基线的配对显著性检验、流行度
分层分析、与研究问题清晰对应的消融实验、超参数敏感
性曲线，以及FLOPs/参数统计。分层基线设计是在共享
骨干下隔离每个文本组件边际贡献的正确方式，而实用性
定位（即TF-IDF是强基线、cross network引起的
HR-ranking trade-off对应候选召回vs.重排序、多视角
在等带宽下略优于单视角）提供了可操作的指导。此外，
该工作看起来高度可复现。

我的主要顾虑是贡献的规模相对于其复杂度。完整的
MV-Align流水线很精细（即四个LLM视角加白化、SE
门控、ℓ2归一化、视角门控、DCN-V2 cross、InfoNCE
对齐、两个独立的冷启动机制，以及两阶段训练方案），
但其相对于最佳文本基线（TF-IDF+单视角LLM）的提升
很小（约+0.17-0.22 pp HR@10，约3%）。结果表明
TF-IDF已经捕获了大部分文本收益，而消融实验表明某些
组件（特别是SE门控）贡献甚微。增益统计显著，但如果
能展示哪些组件实际上是必要的——例如，一个大幅简化
的变体（比如仅TF-IDF+LLM加白化和对齐）是否能匹配
MV-Align——并明确说明增加复杂度的成本-收益论证，
将大大加强论文。

其次，评估局限于两个相似的、非常稀疏的Amazon领域，
一个骨干和一个LLM，且省略了任何外部文本增强序列
推荐模型；分层设计对于RQ来说是合理的，但如果没有
至少一个外部基线（如UniSRec风格的方法）和第二个
领域或骨干，很难判断MV-Align的竞争力或发现的
泛化性。

第三，冷启动的story是混合的：在Beauty上，添加文本
（包括MV-Align）使HR_new低于ID-only（1.76 vs.
1.88），所以冷启动收益依赖于NDCG/MRR而非HR。
我建议明确说明冷启动收益体现在NDCG/MRR而非
Hit Rate上，并解释为什么文本降低了Beauty上新物品
的Hit Rate。

----------- 关键澄清问题 -----------
1. 鉴于TF-IDF捕获了大部分增益、SE门控是"边际
   的"、且MV-Align仅比TF-IDF+LLM提高约3%
   HR@10，一个大幅简化的变体（例如仅TF-IDF+LLM
   加白化+对齐——去掉SE门控、双冷启动重加权和
   两阶段训练方案）能否匹配MV-Align？哪些组件
   对于报告的增益实际上是必要的？

2. 这些发现（白化有助于多视角；cross的HR-ranking
   trade-off；多视角>单视角）是否在第二个领域/
   骨干或不同LLM上成立，还是特定于稀疏Amazon
   数据+SASRec+Qwen2.5-7B？

3. MV-Align与至少一个现有文本增强序列推荐模型
   （如UniSRec风格）相比表现如何？没有这个比较，
   与该领域的竞争力不明确。

4. 为什么添加文本会使新物品HR低于ID-only？冷启动
   收益是否最好被描述为排序质量（NDCG/MRR）的
   收益而非HR的收益？
